# asterisk_chan_simbox

[🇬🇧 English](README.md) | [🇷🇺 Русский](README_ru.md)

## Обзор

**asterisk_chan_simbox** — промышленный форк драйвера каналов [chan_dongle](http://code.google.com/p/asterisk-chan-dongle/) для Asterisk PBX, разработанный **Антоном Додоновым** и командой **[Native Mind](https://nativemind.net)**. Изначально известный как **chan_svistok**, проект значительно вышел за рамки оригинального chan_dongle за 2+ года промышленной эксплуатации с управлением **500+ Huawei UMTS 3G модемами** одновременно.

Этот репозиторий объединяет:
- **`asterisk_chan_svistok/`** — проверенный в бою драйвер (read-only)
- **`asterisk_chan_dongle/`** — форки сообщества для совместимости с Asterisk 20+ (read-only)
- **`adapters/`** + **`src/`** — новый адаптерный слой (архитектура Strangler Fig) для автономной работы без Asterisk

## Основные доработки относительно оригинального chan_dongle

### 🔍 Node Discovery — 3 поколения авто-обнаружения устройств

Оригинальный chan_dongle имеет единственный примитивный механизм обнаружения устройств (`pdiscovery.c`). chan_svistok прошёл через **три поколения** discovery, каждое из которых решало реальные эксплуатационные проблемы при масштабировании:

| Поколение | Файл(ы) | Архитектура | Назначение |
|-----------|---------|------------|-----------|
| **Gen 1** — Legacy | `pdiscovery.c` | In-process, синхронный | Оригинальный подход chan_dongle. Блокирует Asterisk при перечислении USB. Работает для 1–5 модемов. |
| **Gen 2** — In-Process Async | `simnode/adiscovery_core.c` | In-process, асинхронный с потоками | Текущий в live-модуле Asterisk. Неблокирующее обнаружение для десятков модемов. |
| **Gen 3** — Standalone Daemon | `simnode/adiscovery_core_new.c` + `adiscovery_simnode.c` | Внешний демон, IPC | Полностью отвязан от Asterisk (`#ifdef IN_SIMBOX` отключает Asterisk includes). Для 100+ модемных узлов, работает самостоятельно на безголовых устройствах. |

**Что делает система обнаружения:**
- Перечисляет все `/dev/ttyUSB*` устройства в системе
- Отправляет AT-команды идентификации (`ATI`, `AT+CIMI`, `AT^SN`) на каждый порт
- Сопоставляет найденные модемы с конфигурацией по **серийному номеру (S/N)** — не по IMEI
- Учитывает топологию USB хабов для многопортовых шлюзов
- Кэширует найденные устройства для ускорения последующих сканирований

### 🔧 Программатор — встроенный Qualcomm DIAG прошивальщик

Оригинальный chan_dongle **не имеет никаких** возможностей управления прошивкой. chan_svistok включает полноценный встроенный **программатор по протоколу Qualcomm DIAG** для модемов Huawei (E1550, E173, E171):

```
chan_svistok/programmator/
├── ttyprog_programmator.c    # Точка входа программатора
├── ttyprog_core.c            # Реализация протокола DIAG
├── tty_v2.c                  # Низкоуровневый I/O для DIAG режима
└── addons.c                  # Сохранение состояния и отслеживание прогресса
```

**Ключевые возможности:**
- **Прошивка кастомной прошивки** через DIAG mode — модем предварительно переводится в DIAG режим
- **Отслеживание прогресса прошивки** через конечный автомат: `init` → `diag` → `wait` → `flash` → `done`
- **Сохранение состояния на устройство** при многоэтапных операциях
- **Реализованные функции кастомной прошивки:**
  - Корректная отдача **S/N (серийного номера)** через `AT^SN` — для надёжной идентификации устройства при отсутствии SIM-карты
  - Смена **IMEI одной AT командой** — без перепрошивки (подробнее ниже)

#### 🛡️ Восстановление модемов и статистика надёжности

> **Статистика надёжности за 2 года непрерывной эксплуатации 500+ модемов:**
>
> - 🟢 **Умер только 1 модем** из 500 — и, вероятно, от старости/аппаратного износа, а не от прошивки
> - 🟢 **Успешно восстановлены все, кроме 2** из 10+ принесённых на ремонт убитых модемов
> - 🟢 2 невосстановимых модема имели **аппаратные повреждения** за пределами возможностей DIAG mode

**Процесс восстановления убитых модемов:**
1. Перевод модема в **DIAG mode** (диагностический режим Qualcomm через USB)
2. Прошивка кастомной прошивки через встроенный программатор
3. Модем перезагружается с корректным S/N, дефолтной AT-конфигурацией и рабочим состоянием
4. Авто-discovery подхватывает модем и вводит его в строй

**Авто-восстановление «зависших» модемов:**
- Улучшенная функция `port_status()` для мониторинга доступности USB устройства
- Автоматическое восстановление состояния устройства при потере связи
- Улучшенный перезапуск потока мониторинга при переподключении устройства
- Авто-сброс к дефолтному состоянию когда модем перестаёт отвечать

### 📖 Reader — APDU ридер SIM-карт (без радиомодуля)

Оригинальный chan_dongle **не поддерживает ридеры SIM-карт**. chan_svistok включает самостоятельный модуль `reader/` для работы с **USB SIM-ридерами** через APDU (Application Protocol Data Units):

```
chan_svistok/reader/
├── reader_core.c    # Реализация APDU команд, парсинг ATR
└── reader_core.h    # API определения ридера
```

**Что делает ридер:**
- Общается с USB ридерами SIM-карт (радиомодуль GSM не нужен)
- Отправляет/принимает APDU команды к SIM-картам
- Парсит ATR (Answer to Reset) ответы
- Управляет линиями RTS/DTR для аппаратного сброса ридера
- Полностью независим от модемной/звонковой подсистемы — нет вызовов, SMS, регистрации в сети

### 🔑 Смена IMEI одной AT командой (без перепрошивки!)

В оригинальном chan_dongle IMEI — статический и read-only.

В chan_svistok с **кастомной прошивкой** IMEI можно поменять **на лету** одной AT командой через CLI Asterisk:
```
dongle cmd <device> AT+EGMR=1,7,"<новый_IMEI>"
```

- Перепрошивка **не требуется**
- Вступает в силу немедленно
- Автоматически вызывает перезапуск устройства при изменении конфигурации IMEI (обнаружение критических изменений конфигурации)
- Сохраняется в NVRAM модема между перезагрузками

### 🆔 Идентификация устройств по S/N (не по IMEI)

Это **ключевое архитектурное отличие** от оригинального chan_dongle:

| Аспект | chan_dongle | chan_svistok |
|--------|-----------|-------------|
| **Идентификация устройства** | По IMEI | По **серийному номеру (S/N)** через `AT^SN` |
| **Без SIM-карты** | Ненадёжная идентификация | ✅ S/N всегда доступен вне зависимости от SIM |
| **После смены IMEI** | Идентичность устройства потеряна | ✅ S/N остаётся неизменным, устройство отслеживается корректно |
| **Привязка в конфиге** | Поле `imei=` | Поле `sn=` — привязка к аппаратному S/N |

**Почему S/N важен для simbox-операций:**
- При управлении 500+ модемами SIM-карты часто перемещаются между устройствами
- IMEI может быть изменён по эксплуатационным причинам
- **Аппаратный серийный номер** — единственный по-настоящему постоянный идентификатор
- Без вставленной SIM-карты IMEI может быть нечитаем — но S/N доступен всегда
- Кастомная прошивка обеспечивает корректную отдачу S/N через ответ `AT^SN`

### 🔄 Улучшенная стабильность модемов и авто-восстановление

| Функция | chan_dongle | chan_svistok |
|---------|-----------|-------------|
| Обнаружение отключений | Базовое | Улучшенный мониторинг USB через `port_status()` |
| Восстановление при сбое | Простое переподключение | Полноценная машина состояний |
| Варианты перезапуска | Один вариант | 3 режима: `now`, `gracefully`, `when convenient` |
| Машина состояний рестарта | Нет | `stop` → `restart` → `remove` → `start` |
| Перезапуск при смене конфига | Ручной | Автоматический при критических изменениях (TTY, IMEI, IMSI) |
| Отслеживание состояния | Нет | `desired_state` vs `current_state` |
| Очистка ресурсов | Базовая | Полное освобождение ресурсов перед перезапуском |

## Совместимость с Asterisk 20+

chan_svistok изначально построен на **старой базе Asterisk** (эпоха до opaque `ast_channel`, примерно Asterisk 1.8–11). API Asterisk претерпел ломающие изменения в версиях 12–20+.

Два форка сообщества документируют и решают эти проблемы совместимости. Оба включены в репозиторий как **read-only справочные материалы**:

### [pulpoff/asterisk-chan-dongle](https://github.com/pulpoff/asterisk-chan-dongle)

Этот форк добавляет **поддержку Asterisk 20** и документирует точные изменения API:

| Ломающее изменение | Старый API (Asterisk 1.8) | Новый API (Asterisk 20+) |
|-------------------|--------------------------|--------------------------|
| Структура канала | Прямой доступ к полям `ast_channel` | Opaque структура с функциями-аксессорами |
| Форматы кодеков | Legacy format API | `ast_format_cap` / `ast_format_slin` |
| Аллокация канала | `ast_channel_alloc(...)` | `ast_channel_alloc(...)` с параметрами `assignedids`/`requestor` |
| Bridge peer | `ast_bridged_channel()` | `ast_channel_bridge_peer()` |
| Channel request | Старая сигнатура callback | Обновлённый callback `channel_request` |
| Регистрация модуля | Базовый `AST_MODULE_INFO` | Расширенный с `load_pri`/`support_level` |
| Макрос версии | `ASTERISK_FILE_VERSION` | Удалён (deprecated) |

Протестирован с **Asterisk 20.6.0** и Huawei E1762. Также предоставляет Docker-деплой (docker-compose) для быстрого старта на Armbian/ARM платах.

### [wdoekes/asterisk-chan-dongle](https://github.com/wdoekes/asterisk-chan-dongle)

Этот форк (самый популярный форк сообщества, изначально от bg111) предоставляет:

- **`ast_compat.h` / `ast_config.h`** — шим совместимости версий, адаптирующийся к разным версиям Asterisk на этапе компиляции. Ближайший прецедент к адаптерному шиму, строящемуся в этом проекте.
- **`smsdb.c/h`** — БД персистентности SMS (chan_svistok использует файловую персистентность)
- **`gsm7_luts.h`** — таблицы подстановки кодирования GSM 7-bit
- **`error.c/h`** — структурированная обработка ошибок
- Поддерживает Asterisk 14+ с автоматическим определением версии при сборке
- Включает рекомендации по настройке **Jitter buffer** и **AGC (Automatic Gain Control)**

Оба форка используются **только как справочные материалы по паттернам и миграции** — их код не мерджится в chan_svistok. Адаптерный слой в `adapters/`/`src/` строит совместимость непосредственно под API shape chan_svistok.

## Структура репозитория

```
asterisk_chan_simbox/
├── asterisk_chan_svistok/              # READ-ONLY. Боевой проверенный драйвер
│   └── chan_svistok/                   #   Исходный код, программатор, ридер, simnode
│       ├── simnode/                    #   Поколения discovery (Gen 2 и 3)
│       ├── programmator/              #   Qualcomm DIAG прошивальщик
│       ├── reader/                    #   APDU ридер SIM-карт
│       └── tools/                     #   Автономные утилиты (discovery tool)
├── asterisk_chan_dongle/               # READ-ONLY. Справочные форки сообщества
│   ├── asterisk-chan-dongle-by-wdoekes/  # ast_compat.h, smsdb, Asterisk 14+
│   └── asterisk-chan-dongle-by-pulpoff/  # Asterisk 20 поддержка, Docker
├── adapters/                           # НОВОЕ: Asterisk-API-совместимый шим
├── src/                                # НОВОЕ: Код автономного моста
└── flows/                              # SDD потоки разработки
    └── sdd-asterisk-chan-simbox/        # Активная spec-driven разработка
```

> ⚠️ **Жёсткое правило**: `asterisk_chan_svistok/` и `asterisk_chan_dongle/` являются **навсегда read-only**. Весь новый код — в `adapters/` и `src/`.

## Требования

- **ОС**: Linux 2.6.33+ (проверено на Armbian, OpenWRT)
- **Asterisk**: 1.8–20+ (с шимом совместимости)
- **Оборудование**: Huawei UMTS модем с USB интерфейсом
- **SIM**: PIN-код должен быть отключен
